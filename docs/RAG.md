# SkillLens AI — True RAG Pipeline Technical Specification

**Service Module**: `backend/app/services/rag_service.py`  
**Storage Path**: `backend/data/vector_indexes/{document_id}.npz`  
**Embedding Dimensions**: 384-dimensional dense semantic vector space  
**Chunking Policy**: 800-1200 tokens (3200-4800 characters) with 100-200 token overlap

---

## 1. Architectural Principles

SkillLens AI implements **True RAG** (Retrieval-Augmented Generation) rather than ungrounded LLM prompting. In civil service capacity building, questions must never hallucinate rules, administrative codes, or statistical formulas.

Every assessment item generated by SkillLens conforms to the **Provenance Guarantee**:
$$\text{Question} \xrightarrow{\text{verbatim link}} \text{Document Chunk} \xrightarrow{\text{page \& section}} \text{Official Manual / Circular}$$

---

## 2. End-to-End Pipeline Execution

```
[Official Document (PDF/DOCX/TXT)]
                │
                ▼
      Text Extraction & Normalization
                │
                ▼
       Sliding-Window Chunking (800-1200 tokens, 150 token overlap)
                │
                ▼
       Metadata Tagging (Document ID, Chunk Index, Page, SHA-256 Hash)
                │
                ▼
   Dense Vector Embedding Generation (384 Dimensions)
                │
                ▼
 Persisted Local Vector Index (backend/data/vector_indexes/{doc_id}.npz)
                │
                ▼
 [User Assessment Request / Topic Query]
                │
                ▼
  Dense Query Embedding -> Cosine Similarity Top-K Retrieval (k=5)
                │
                ▼
 Grounded Prompt Assembly (Strict Negative Constraint Injection)
                │
                ▼
 LLM Question Synthesis with Verbatim Source Excerpt & Page Reference
```

---

## 3. Chunking Strategy & Cryptographic Hashing

Text is partitioned using semantic boundary detection (paragraph breaks `\n\n`, section headers, or periods):
- **Target Size**: 800 to 1,200 tokens.
- **Overlap**: 100 to 200 tokens (preserves context across chunk boundaries).
- **Chunk Hash**: SHA-256 computed on the exact raw string:
  ```python
  chunk_hash = hashlib.sha256(snippet.encode("utf-8")).hexdigest()
  ```
- **Heading Detection**: Heuristic extraction of capitalized section titles (e.g. `Section 1: Multi-stage Stratified Sampling`).

---

## 4. Vector Store & Embedding Implementation

1. **Embedding Model**:
   - Primary: SentenceTransformers `all-MiniLM-L6-v2` (384 dimensions).
   - Fast Deterministic Fallback: MD5 hash-space n-gram projection with L2 vector normalization.
2. **Persistence**:
   - Compressed `.npz` archive saved per document.
   - Contains `vectors` (matrix of shape $N \times 384$) and `metadata` (JSON serialized chunks, text excerpts, page numbers, hashes).
3. **Retrieval**:
   - Cosine similarity computed via dot product between normalized chunk vectors and query embedding:
     $$\text{Score}_i = \mathbf{V}_i \cdot \mathbf{Q}$$
   - Filtered by threshold (`min_score = 0.05`) and sorted in descending order to return top-k chunks.

## 6. Question Versioning & Auditability

Generated questions are not ephemeral:
- Registered as version 1 in the item bank (`QuestionVersion` table).
- Tagged with `source_document_id` and initial status `ACTIVE`.
- When an administrator runs the Syllabus Pattern Watcher and flags updated curricula, existing questions tied to modified topics transition to `REVIEW` status, ensuring outdated questions are never served to civil servants.
